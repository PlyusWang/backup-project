# 定时与实时备份使用说明

定时备份按周期检查源目录，实时备份在检测到文件变化后检查源目录。两者均支持
完整和增量策略，以及不加密、AES 和 DES 兼容模式；实际执行由客户端进程负责。

## 1. 选择备份方式

| 设置 | 行为 |
| --- | --- |
| 完整备份（`full`） | 检测到变化时生成可独立恢复的完整快照；已有可用基线且没有变化时跳过 |
| 增量备份（`incremental`） | 首次建立完整基线，之后保存新增、修改、删除和元数据变化；恢复时需要对应父链 |
| 定时触发 | 按保存的周期检查，GUI 还可点击“立即执行一次” |
| 实时触发 | Linux 上递归监听源目录，合并短时间内连续变化；启用或重新建立监听时会检查当前内容 |

打包格式可选 MyPack、USTAR、Fast USTAR；三者都能用于完整和增量备份。
增量文件使用 Backup Project 的外层格式记录依赖与删除信息，内部变化文件可以
使用 USTAR 编码，但整个增量 `.bak` 不能直接当作标准 tar 使用。

新配置的压缩方式为不压缩、Huffman、Zstd。Zstd 是手写 RFC 8878 受限子集，
支持范围及旧版读取器限制见 [Zstandard 格式说明](ZSTANDARD_FORMAT.md)。
已有 `lzss-huffman` 配置会额外显示“LZSS + Huffman（旧格式）”；保存其它字段
不会自动改变压缩算法，只有明确选择其它算法并保存后才迁移。

源目录、目标仓库、筛选规则、打包、压缩或加密策略变化后，旧基线可能不再兼容。
需要建立新完整基线时，运行结果会说明原因；不能把新基线当作真正的增量。
无变化时不会创建空的增量文件。更换归档密码不会重写旧链；恢复旧链仍需旧密码。

## 2. GUI：配置、保存与启停

先在“设置”页配置本地仓库，再打开“自动备份”或“实时备份”页。选择源目录、
备份策略和目标仓库；定时页填写周期，实时页填写响应延迟与最长等待时间。
高级设置提供打包、压缩、加密和筛选规则。

| 操作 | 使用的配置与结果 |
| --- | --- |
| 保存设置 | 校验并保存当前草稿，保持原有启用或停用状态 |
| 启用 | 校验并保存当前草稿，成功后才显示已启用；保存失败时不启用 |
| 停用 | 保存停用状态并停止接受新的自动触发；其它未保存的编辑仍是草稿 |
| 定时页“立即执行一次” | 先保存当前草稿，再执行检查；保存失败时不执行 |

页面显示“改动尚未保存”时，已运行的服务继续使用已保存配置；不能把编辑框中的
草稿当作已经生效。“立即执行一次”只在计划实际启用且当前运行条件允许时可用，
不需要再按一次保存才能解锁。它跳过到期时间检查，仍执行变化检测，因此成功结果
也可能是“没有变化，已跳过”，并不保证产生新快照。

定时任务首次启用后，下次自动运行排在一个完整周期之后；需要立即检查时使用
“立即执行一次”。保存已启用计划的其它设置不会重新开始一个启用周期。
实时任务启用后会建立监听并检查当前源目录，首次运行可能建立完整基线。

停用成功后，新文件变化不应再触发备份。已经完成的历史记录、旧的成功提示和
快照列表仍会保留，它们不能用来判断监听仍在运行。任务运行期间操作按钮可能
暂不可用；等待当前任务结束后停用，并确认页面显示已停用、实时监听已停止。
需要验证停用是否生效时，记录现有快照名，再修改一个已被规则包含的文件，检查
是否出现新的任务事件和快照；仅看到旧历史不代表又运行了一次。

## 3. 加密与重启后的密码状态

普通 GUI 用法是选择 AES，输入并确认归档密码，再保存或启用。密码只保存在
当前进程的会话内存中，配置中保存的是会话引用，不是密码本身。定时与实时任务
分别使用各自的凭据；网络服务器的登录密码也不等于归档密码。

退出或重新打开 GUI 后，会话密码失效。已保存的启用标记可能仍为启用，但没有
重新解锁归档密码之前，加密任务不能成功执行。回到相应页面输入并确认原密码，
保存设置后再检查运行状态；停用的任务还需明确启用。缺少密码或密码读取失败时
程序报错，不会自动改用不加密备份。新密码草稿保存失败时，不能据此认为正在运行
的任务已经改用新密码。

高级用法可指定由用户自己维护的口令文件，GUI 与 CLI 共用以下检查：

- 必须是当前用户拥有的普通文件，不能是符号链接、目录或设备；
- 必须使用绝对路径，文件仅属主可访问，例如权限 `0600`，且属主可读；
- 文件长度为 1～4096 字节，不含 NUL；读取时只去掉末尾一个换行或 CRLF；
- 配置只保存文件路径；文件本身含归档密码，应放在个人受保护的目录中。

程序不会自动创建保存明文密码的文件。CLI 的 `--password-file` 参数传的是
文件路径，不能把密码写在参数、环境变量或命令历史中。GUI 会话引用不能被另一个
CLI 进程解锁或继承；需要 CLI 自动任务时，由用户明确提供符合检查的口令文件。

DES 模式用于课程兼容，普通数据备份应选择 AES。保存好归档密码；没有正确密码
无法恢复加密快照，服务器管理员也不能替用户解密。

## 4. CLI：本地定时备份

下列命令在安装客户端的 Linux 机器上运行。将示例路径替换为自己的路径，并在
运行 CLI 前退出同一用户下正在运行的 GUI 或另一个客户端进程。

```bash
backupctl config repository set /home/user/backup-repository
backupctl schedule set \
  --source /home/user/data \
  --interval-minutes 60 \
  --retain 12 \
  --strategy incremental \
  --pack mypack \
  --compression zstd \
  --encryption none
backupctl schedule show
backupctl schedule enable
backupctl schedule run
backupctl schedule history
```

`schedule set` 保留已有启用状态；不会仅因保存配置就自动启用。
修改已启用计划时，会同时校验源目录、仓库与凭据是否可用；校验失败保留旧配置。
`schedule run` 要求已启用，只检查一次，不启动后台循环。

要持续按周期运行，执行：

```bash
backupctl schedule watch
```

它在前台运行，Ctrl+C 退出并释放锁。退出 watcher 只停止当前进程，不自动清除
保存的启用状态。退出后可持久停用：

```bash
backupctl schedule disable
```

CLI 加密计划使用已有的受保护口令文件，例如：

```bash
backupctl schedule set \
  --encryption aes-256-ctr-hmac-sha256 \
  --password-file /home/user/.config/backup-project-secrets/archive-password
```

这里的文件必须由用户事先准备并满足第 3 节的检查。可以保存停用配置再启用；
启用、立即执行和每次实际运行都不会因缺少凭据而降级。

筛选规则示例：

```bash
backupctl schedule set --clear-filters \
  --include 'ext:txt;md' \
  --exclude 'path:**/build/**'
```

`--include`、`--exclude` 可重复；没有 `--clear-filters` 时追加到已有规则。
有 `--clear-filters` 时先清空旧规则，再加入本次命令中的全部规则，与参数顺序
无关。`--source`、`--strategy`、`--pack`、`--compression` 等单值参数不允许重复。

可用的全局路径参数包括 `--config-file <path>`、`--schedule-file <path>`。
查看当前配置与结果使用 `schedule show`、`schedule history`；原始技术诊断不应
被当作备份成功的依据，应同时检查结果类型和新快照名。

## 5. CLI：本地实时备份

```bash
backupctl realtime set \
  --source /home/user/data \
  --debounce-ms 500 \
  --max-wait-ms 5000 \
  --retain 12 \
  --strategy incremental \
  --pack mypack \
  --compression zstd \
  --encryption none
backupctl realtime enable
backupctl realtime watch
```

响应延迟范围为 100～60000 ms；最长等待为 500～300000 ms，且不能小于响应
延迟。短时间内多次变化会合并，持续变化也会在最长等待限制内触发一次检查。
首次启用或重新建立监听会检查源目录；有可信基线且无变化时不会创建伪快照。

需要加密时，同样在 `realtime set` 中指定 AES 和 `--password-file`。
Ctrl+C 退出前台监听后，可运行：

```bash
backupctl realtime disable
backupctl realtime show
backupctl realtime history
```

不要在 watcher 仍运行时再开第二个 CLI 修改配置；客户端的单实例保护会拒绝它。
GUI 里直接使用同一页面的停用按钮。

## 6. 运行条件与恢复

定时和实时都只在 GUI 或对应的 CLI watcher 运行期间触发。保存为“已启用”不等于
安装了后台服务；关掉客户端后不会继续执行，服务器的 systemd 服务也不会代替
客户端扫描本地文件。当前每个配置各有一个定时任务和一个实时任务，没有多任务
列表或 cron / 日历规则编辑器。

客户端同一用户下只允许运行一个产品进程；纯 `--help` 不抢锁。误开第二个实例
返回退出码 3。操作失败为 1，用法错误为 2，成功为 0；“无变化跳过”也属于成功。
runner 和仓库锁由内核持有，进程退出或崩溃后释放，不需要删除锁文件。

恢复时使用“备份管理”页，或在对应仓库下选择实际文件名：

```bash
backupctl repository list
backupctl restore 实际快照名.bak /home/user/restored-data
```

目标必须是不存在的新目录或空目录；不覆盖已有文件。恢复内容直接放在目标目录
中。加密归档会要求正确的归档密码；CLI 从交互终端读取，不能通过管道输入。

增量快照必须保留完整基线、所有依赖父快照及关联副文件。不要只复制最后一个
`.bak`，也不要手工删除父快照或身份文件。保留策略会保护仍被后代使用的祖先，
因此实际文件数量可能超过“保留版本”的数值。使用程序的管理入口删除；手工备份
不会仅因出现在同一目录就成为自动任务可淘汰的数据。

定时/实时页还可选择已连接的云端仓库。云端登录会话与归档密码是两项独立条件，
任一失效都会阻止对应任务执行；自建服务器与连接方式见
[自建服务器指南](self-hosted-server.md)和[网络备份说明](network_backup_usage.md)。

## 7. 配置与失败处理

默认配置目录为：

```text
$XDG_CONFIG_HOME/backup-project/backup-gui-modern/
  config.json
  schedule.json
  schedule-manifest.dat
  realtime.json
```

未设置有效绝对路径 `XDG_CONFIG_HOME` 时使用 `$HOME/.config`。
配置文件权限为 `0600`；保存使用同目录临时文件、fsync 和原子替换。
不要手工修改 schema 字段，也不要把会话引用替换成密码。

配置结构、参数组合或规则不合法时，程序明确报错，不会悄悄换成默认策略。
GUI 修正并成功保存后可恢复；CLI watcher 若已退出，应修正后重新启动。
源目录不可读、仓库不可用、空间不足、密码未解锁或网络认证失败时，也应按实际
错误修正；失败不会自动改用不加密，恢复失败不能发布半成品目标。

快照、清单和任务状态需要分别落盘。崩溃可能让某份已完成快照暂时未被任务状态
认领，但不应因此误删它；重新打开程序后检查仓库列表、依赖关系与运行历史。
历史成功只说明那一次运行，不能证明现在的配置、密码和监听仍然可用。

## 8. 变化检测的范围

增量策略使用内容摘要判断普通文件变化，可以识别大小和 mtime 都保持不变的
内容改写。定时完整策略目前仍以路径、类型、大小、mtime、mode、uid/gid、
链接和设备信息进行变化检测；人为同时保持大小与 mtime 的原地改写可能被跳过。
需要检测这种变化时选择增量策略，或明确运行一次手动完整备份。

目录自身的 mtime 不作为自动任务的独立变化触发条件，目录权限或所有权变化会
参与比较；目录 mtime 仍随归档保存和恢复。被筛选规则排除的内容变化不应产生
新的增量数据。运行中源文件持续被其它程序改写时，应先使数据稳定，再检查备份
和恢复结果；自动触发次数不等于有效还原点数量。
