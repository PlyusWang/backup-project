# Zstandard 压缩格式与兼容范围

容器 `BKPCNT2` 的压缩编号新增 `3`（键 `zstd`）；编号 `0`（不压缩）、`1`（HUF1）和 `2`（LZH1）保持原义，旧归档继续可读。旧版读取器会明确拒绝未知编号，不会误解为不压缩。压缩后仍走同一套容器认证、加密与恢复事务；压缩算法不承担密码认证。

实现依据 RFC 8878 与 XXH64 公开格式说明，编码、LZ 匹配、Huffman、FSE 与 XXH64 均在 `src/compression/zstd.cpp` 中自行实现，没有链接现成压缩或哈希库。`zstd` 命令仅用于独立互操作验证。

## 编码器

输出单个标准 Zstandard frame：128 KiB 声明窗口、64 KiB 独立匹配块、显式 64 位原始长度和低 32 位 XXH64 内容校验。变化文件与完整归档使用相同压缩流水线。

匹配使用块内哈希索引；序列使用标准预定义 FSE 表。字面量使用原始字节或显式权重 Huffman 表（单个或四个反向比特流）。不能缩小的块回退为标准 raw block。该策略侧重可核查的手写实现，压缩比和速度不等同于完整参考编码器。

## 解码器

支持 raw、RLE、compressed block；支持 raw、RLE、显式权重 Huffman literals；支持预定义与 RLE FSE 序列表、重复偏移、可选内容校验与不同长度字段。

以下合法扩展不在当前读取范围内，遇到时明确拒绝：FSE 压缩的 Huffman 权重、复用 Huffman 表、动态或复用 FSE 序列表、字典、拼接帧、skippable frame，以及声明窗口超过 8 MiB 的帧。因此本读取器是明确受限的标准子集，不能声称可解压任意 `.zst` 文件。应用归档中的 Zstandard 流由本编码器生成，均在此范围内。

按 RFC 8878 §3.1.1.2.3–.4，同时限制压缩和解压块长不超过 `min(window, 128 KiB)`。参考工具对某些小 single-segment 帧更宽松；本实现继续执行规范上限。

## 资源与失败处理

文件接口只按块读写，不把整个归档或解压结果放入内存。解码历史是最多 8 MiB 的环形缓冲，块缓冲最多 128 KiB，输入输出沿用固定缓冲。字符串接口只供已知小数据与测试使用。

调用方必须给出来自外层容器的期望原始长度；有内容长度字段时在写输出前核对，逐块检查累计输出上限，结束时严格核对长度、校验值和 EOF。畸形熵表、截断、超界偏移、剩余比特及尾随内容均拒绝。

文件输出使用现有 `FileSink`，编解码器不创建、替换或删除用户最终目标。流水线失败时丢弃私有临时文件，恢复结果只在全部解压与归档校验通过后发布。字符串接口失败时保持调用方原有输出不变。

GUI 新配置提供不压缩、Huffman、Zstd。已有 LZSS + Huffman 自动任务会显示“旧格式”项并保持原配置和执行能力；只有用户明确选择其他算法并保存后才迁移。CLI 的 `lzss-huffman` 兼容键保留。

## 运行独立回归

安装独立标准工具 `zstd` 后，从源码仓库运行：

```bash
make zstd-codec BUILD_DIR=build-zstd CXXFLAGS='-std=c++17 -O2 -Wall -Wextra -Wpedantic'
make test-zstd BUILD_DIR=build-zstd ZSTD_TEST_OUTPUT=/absolute/new/test-output
```

输出目录必须尚不存在，避免覆盖前次记录。测试包括三种规模与五种数据、标准工具双向验证、格式拒绝、篡改与截断、字符串失败不变、旧算法往返，以及现存目标和符号链接保护。测试夹具不启动产品 CLI、GUI 或服务器。
